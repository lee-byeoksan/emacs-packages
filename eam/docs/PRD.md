## 1. 제품 정의

**EAM은 Emacs 안에서 공식 AI CLI를 사용하면서, Emacs 재시작에도 작업을 유지하고 필요할 때 입력과 대화를 일반 버퍼에서 다루게 하는 키보드 중심 개발 패키지다.**

사용자는 익숙한 Claude Code 또는 Codex의 입력창에서 파일 수정·테스트·모델 선택·승인을 수행한다. EAM은 프로젝트별 세션을 관리하고, 입력 편집과 저장 대화 조회를 Emacs의 편집 경험에 연결한다. AI 요청을 대신 설계하거나 자동 분배하지 않는다.

핵심 가치는 다음 세 가지다.

1. **작업 연속성:** Emacs를 닫아도 실행 중인 CLI를 유지하고 같은 프로세스에 다시 연결한다.
2. **입력·읽기 편의:** 터미널 직접 입력을 기본으로 하되 한글·긴 요청은 일반 버퍼에서 편집하고 긴 응답은 제한된 대화 페이지로 읽는다.
3. **사용자 통제:** 공식 CLI의 기능과 구독 로그인 경로를 활용하고, EAM이 추가하는 AI 호출·컨텍스트·설정을 최소화한다.

## 2. 문제와 대상 사용자

### 2.1 해결할 문제

| 사용자 상황 | 불편과 실패 가능성 | 제품이 제공할 결과 |
| --- | --- | --- |
| Emacs에서 작업하며 외부 AI 터미널을 병행 | 프로젝트·입력·응답을 여러 창에서 추적해야 함 | Emacs 안에서 CLI 사용과 세션 선택 |
| Emacs를 자주 재시작 | 편집기 수명에 묶인 CLI가 종료될 수 있음 | CLI 프로세스와 Emacs 표시의 수명 분리 |
| 한글 또는 여러 줄 요청 작성 | 터미널 입력 편집이 불편할 수 있음 | 일반 버퍼 편집과 기존 입력의 왕복 |
| 여러 프로젝트에서 동시 작업 | 연결 중·분리·종료를 혼동하기 쉬움 | 살아 있는 세션 목록과 명확한 분리·종료 동작 |
| AI 출력이 길어짐 | 요청을 잊거나 필요한 응답을 찾기 어려움 | CLI 저장 대화와 마지막 저장 요청 조회 |
| 대화·로그가 계속 쌓임 | 큰 버퍼·undo·중복 저장으로 자원이 증가 | 제한된 표시, 출력 undo 비활성, 원시 기록 선택 저장 |
| 기존 AI 도구의 자동 기능 사용 | 원하지 않는 컨텍스트와 추가 호출이 발생할 수 있음 | 명시적 입력·전송, 로컬 정보 기반 보조 기능 |

한글 문제가 모든 터미널에서 항상 발생한다는 전제는 두지 않는다. 실제 IME 조합 문제와 Computer Use의 입력 전달 문제를 구분한다.

### 2.2 주 사용자와 사용 맥락

주 사용자는 M-x, 버퍼, 키 바인딩, use-package를 사용하는 macOS 개발자다. 하나 이상의 공식 CLI에 로그인해 있고, 여러 프로젝트·worktree를 오가며 Emacs를 재시작한다. GUI 메뉴 없이 작업하는 것을 선호한다.

첫 도입 대상은 제품을 함께 검증하는 개인 사용자다. 조직 공용 운영, 원격 다중 사용자 서비스, Emacs 초보자를 위한 완전 자동 설치는 현재 제품 범위가 아니다. 사용자 수·유료 전환율·시장 규모는 조사하지 않았으며 본 문서에서 추정하지 않는다.

### 2.3 대표 사용 목적

> “Emacs에서 작업을 계속하면서 AI CLI의 기능을 그대로 사용하고 싶다. 편집기를 재시작해도 작업이 남아 있어야 하고, 긴 요청과 응답은 필요할 때 Emacs 버퍼에서 편하게 다루고 싶다.”

## 3. 확정된 원칙과 범위

### 3.1 제품 원칙

- Orca·Paseo 및 Emacs AI 패키지에서 개념을 참고하되 포크를 제품 기반으로 삼지 않는다. Ghostel은 원본 의존성으로 사용한다.
- 명령에 provider 이름을 내장하지 않는다. 명령 실행 중 자동완성으로 Claude 또는 Codex를 선택한다.
- 기본 입력은 실제 터미널 입력이다. 별도 버퍼 편집은 필요할 때 선택한다.
- 모든 사용자용 실제 CLI 세션은 지속 세션이다. 별도의 일반/지속 세션 모드를 제공하지 않는다.
- EAM의 시스템 프롬프트·스킬·프로젝트 파일·요약을 자동 삽입하지 않는다. 사용자가 선택한 diff나 텍스트만 명시적 동작으로 초안에 넣는다.
- 세션 목록·기록 조회·상태 확인·알림 분류를 위해 AI를 호출하지 않는다. CLI가 자체적으로 수행하는 모델 호출·재시도·압축은 별개의 동작이다.
- 인터페이스의 기준은 M-x와 키 바인딩이다. 시작 대시보드나 GUI 메뉴는 제공하지 않는다.
- 개인 Emacs 설정·CLI 설정 파일을 자동 수정하지 않는다. 설정값을 사용자가 적용하는 방식과 격리된 시험 프로필을 지원한다.
- 정상 종료와 조회 실패를 구분한다. 출력 바이트 증가만으로 모델이 작업 중이거나 작업이 끝났다고 판정하지 않는다.

### 3.2 현재 범위

| 핵심 범위 | 보조 범위 | 제외·미지원 범위 |
| --- | --- | --- |
| 공식 CLI 실행·직접 입력 | 완료·승인 요청 알림 | EAM 자체 task 실행기 |
| 지속 세션 목록·재접속·종료 | 선택 diff 리뷰 초안 | 자체 AI 에이전트·자동 작업 분배 |
| 기존 CLI 입력의 외부 편집기 왕복 | Git worktree 관리 | 독자 모델 선택 UI·slash 명령 재구현 |
| CLI의 저장 대화 재개 | 수동 세션 전환 | 재부팅 후 같은 프로세스 복원 |
| native 대화·마지막 요청 조회 | 수동 Caffeine | native 대화 전체 검색·자동 요약 |
| 일반 Emacs에 설치·별도 프로필 시험 | 선택적 원시 기록·진단 도구 | 첨부·이미지·파일 칩의 호환 보증 |

초기 가짜 스트림과 JSON 연결 실험은 개발 이력이다. 일부 과거 어댑터 코드는 남아 있지만 현재 권장 제품 흐름은 Ghostel의 대화형 CLI다. 테스트용 `eam-demo-*`는 배포 tar에 포함하지 않는다.

## 4. 사용자에게 구분되어야 하는 개념

| 개념 | 의미 | 수명과 데이터 |
| --- | --- | --- |
| EAM 세션 | 프로젝트에서 실행한 공식 CLI와 표시 연결의 관리 단위 | CLI를 종료할 때까지 지속 가능 |
| 표시 연결 | Emacs와 실행 중인 CLI의 연결 | 분리하거나 Emacs를 닫으면 끊김 |
| CLI 저장 대화 | provider가 로컬에 저장한 요청·응답 | 프로세스가 종료되어도 CLI 저장 정책에 따라 남음 |
| 외부 편집 버퍼 | CLI의 기존 입력을 편집하는 임시 버퍼 | 저장·반환 또는 취소·반환 |
| 보조 초안 | EAM에서 따로 작성하는 텍스트 | CLI 입력과 자동 동기화되지 않음 |

**attach와 resume은 다른 목적이다.** attach는 살아 있는 같은 프로세스에 돌아가고, resume은 새 CLI를 실행해 provider의 저장 대화를 선택한다. history는 저장 내용을 읽기만 하며 프로세스를 시작하지 않는다.

활성 목록에는 `attached`와 `detached`만 노출한다. `running`은 내부 프로세스 상태이며 모델 생성 상태가 아니다. 내부적으로 `exited`, `stopped`, `unavailable`, 표시 연결의 `disconnected` 등 진단 상태가 남아 있다. 사용자에게는 각각 종료 정리 중/종료 확인/상태 미확인으로 설명해야 한다. 상태 미확인 항목은 활성 세션으로 단정하지 않고 개수를 알린다.

## 5. 핵심 사용자 시나리오

| ID | 시작 상황과 동작 | 기대 결과 | 실패·예외 처리 |
| --- | --- | --- | --- |
| U01 | 프로젝트 버퍼에서 `eam-new` → provider → 프로젝트 선택 | 공식 CLI 입력창에서 직접 요청하고 CLI가 수정·테스트·승인 처리 | 의존성 누락 또는 선택 취소 시 시작하지 않음 |
| U02 | CLI에 한글·긴 요청을 쓰다가 `eam-edit-input` | 기존 입력을 일반 버퍼에서 수정 → `C-c C-c` → CLI에서 확인 후 RET | `C-c C-k`는 중간 저장 여부와 무관하게 편집 전 입력으로 복원 |
| U03 | 긴 작업 중 `eam-detach`, Emacs 종료 후 다시 시작 | `eam-attach` 목록에서 같은 CLI 프로세스에 재접속 | 다른 Emacs에 연결 중이면 먼저 그쪽에서 분리 |
| U04 | 여러 프로젝트 작업 중 `eam-sessions` | 연결된 항목은 이동, 분리된 항목은 재접속 | 조회 취소 시 연결 불변, 종료 항목 제외 |
| U05 | CLI를 종료했지만 지난 작업을 이어가려 함 | `eam-resume` → provider·프로젝트 → CLI 자체 대화 선택 | UUID 수동 입력을 기본 흐름으로 요구하지 않음 |
| U06 | 응답이 길어 요청과 답변을 다시 읽고 싶음 | `eam-history`에서 저장 대화 선택, `eam-prompt`로 마지막 요청 확인 | 최근 대화를 현재 CLI 대화로 임의 매칭하지 않음 |
| U07 | diff 일부에 대해 AI에 수정 의견을 전달 | 영역·의견·대상 세션 선택 → 초안 검토 → 붙여넣기 → CLI 제출 | 자동 전송·전체 diff 첨부·초과 분량 자동 자르기 없음 |
| U08 | CLI가 완료되거나 승인을 요청 | 알림 목록에서 해당 열린 세션으로 이동 | 닫힌 세션을 자동 재시작하지 않음 |
| U09 | 작업 종료 | CLI 자체 종료 또는 `eam-quit`으로 소유 서버 정리 | 종료 확인 실패를 성공으로 표시하지 않음 |

직접 detach는 보조 초안을 닫으므로 미저장 초안을 먼저 보관해야 한다. CLI의 자동 종료 정리에서는 수정된 초안을 보존한다. 이 차이는 현재 동작이며 향후 UX 검토 대상이다.

## 6. 기능 요구사항과 수용 기준

우선도 P0는 핵심 사용과 데이터·프로세스 안전을 위해 유지해야 하는 요구사항, P1은 이미 제공하는 보조 기능이다. 구현 상태와 검증 수준은 별개이며 검증 범위는 10절에 기록한다.

| ID / 우선도 | 요구사항 | 관찰 가능한 수용 기준 | 현재 상태 |
| --- | --- | --- | --- |
| R01 / P0 | 공식 CLI 실행 | provider·프로젝트 자동완성, 호출 버퍼의 작업 경로 기본 사용, 취소 시 미실행 | 구현 |
| R02 / P0 | CLI 기능 유지 | 파일 수정·테스트·모델 선택·승인 UI를 터미널에서 사용, EAM이 자동 승인하지 않음 | 명시된 버전·시나리오 검증 |
| R03 / P0 | 지속 세션 | 새 실행·worktree 실행·대화 재개 PTY 데몬, Emacs 종료 후 attach (PTY 화면 복원 제한) | 구현·통합 검증 |
| R04 / P0 | 활성 목록 | attached/detached만 후보, detached 전용 조회, 취소 시 무변경, 미확인 개수 표시 | 구현 |
| R05 / P0 | 분리·종료 구분 | detach 후 CLI 생존, quit 후 종료 확인, CLI 자체 종료 시 분리 상태에서도 자동 정리 | 구현·이전 세션 설정 차이 있음 |
| R06 / P0 | 대화 재개 | 기본 흐름에서 UUID를 요구하지 않고 CLI 자체 목록으로 이어갈 대화 선택 | 구현 |
| R07 / P0 | 기존 입력 편집 | 한글·여러 줄·undo, commit 시 저장·반환, cancel 시 원문 복원, 자동 제출 없음 | 텍스트 왕복 검증 |
| R08 / P1 | 보조 초안 | 독립 초안·명시적 선택 추가·붙여넣기 제공, 기존 CLI 입력과 초안 유지, 전송 상한 초과 거절 | 구현 |
| R09 / P0 | native history | 프로젝트 또는 provider로 대화 선택, 사용자/assistant 텍스트 조회, 원본 수정·대화 복제 저장 없음 | 두 provider 형식 검증 |
| R10 / P0 | 마지막 요청 조회 | 선택한 대화의 마지막 저장 사용자 텍스트, 긴 요청 페이지 이동, 진행 중 여부 미판정 표시 | 구현 |
| R11 / P0 | 제한된 표시·선택 기록 | 과거 페이지도 상한 유지, 출력 undo OFF, 원시 기록 기본 OFF, 설정 후 새 세션에서만 ON | 구현·회귀 검증 |
| R12 / P1 | 세션 알림 | 명시적 이벤트 수신·귀속·중복 병합·읽음·이동, 데스크톱 전달 기본 OFF | 구현·과거 GUI 배너 보고 |
| R13 / P1 | 리뷰 초안 | 선택 diff·경로·줄 위치·의견을 편집 가능한 초안으로 구성, 한도 초과 거절 | diff/Magit 검증 |
| R14 / P1 | worktree | 로컬 ref 기반 생성·탐색·CLI 시작, 변경/ignored 파일 또는 미종료·미확인 세션 존재 시 삭제 보호 | 구현 |
| R16 / P1 | Caffeine | 수동 활성화·표시·해제, Emacs 종료 시 해제, 화면과 시스템의 유휴 잠자기 방지 | 구현 |
| R17 / P0 | 패키지 독립성 | 기존 Emacs에서 로딩 가능, 로딩만으로 GUI/CLI·전역 키 활성화 없음, 제거 후 별도 기록 보존 | 설치 회귀 검증 |
| R18 / P0 | 명령 중심 안내 | 기본 명령·키·실행 위치·후속 동작 설명, GUI 메뉴 불필요, 키 재정의 가능 | 구현, 과거 문서 정합성 보완 필요 |

### 터미널 스크롤 요구사항

기본 PTY 백엔드는 출력을 Ghostel에 직접 전달하며 마우스 모드를 강제하지 않는다. 시작 출력 5MiB 재생 한계와 256KiB 출력 큐 초과 시 연결 해제 정책을 안내한다. 복잡한 TUI의 재연결·터미널 질의 응답·실제 GUI 체감은 추가 검증 대상이다. 모든 세션에 동일한 PTY 경로를 사용한다.

### 6.1 History — 대화와 요청을 다시 읽기

**목적:** 터미널의 긴 출력에서 벗어나 사용자 요청과 AI 응답을 읽고 복사한다. 프로세스 연결 상태와 관계없이 CLI에 저장된 대화를 조회할 수 있어야 한다. R09–R11의 상세 요구사항이다.

**대표 시나리오:** 한 프로젝트에서 Claude 세션 두 개를 사용했다. 긴 응답을 읽다가 요청의 조건을 다시 확인하려고 `C-c a h`를 누른다. 같은 프로젝트의 대화 목록에서 제목·시각·ID를 보고 원하는 대화를 고른다. 최신 페이지를 읽고 `p`로 앞부분을 확인한다. 요청만 보고 싶으면 CLI로 돌아가 `C-c a u`를 실행하고 같은 대화를 선택한다. 조회 과정에서 AI 요청이나 대화 재개는 발생하지 않는다.

| 진입점 | 선택 범위 | 표시 결과 |
| --- | --- | --- |
| `eam-history` / `C-c a h` | 현재 CLI 또는 초안의 provider·프로젝트로 제한 | 선택한 대화의 최근 텍스트 페이지 |
| `eam-history-open` / `C-c a o` | provider 선택 후 해당 저장소의 최근 대화 목록 | 종료된 대화도 포함한 읽기 전용 조회 |
| `eam-prompt` / `C-c a u` | 현재 CLI 프로젝트의 대화 선택 | 마지막 저장 사용자 요청의 첫 페이지 |
| `C-u C-c a o` | 사용자가 원시 TXT/ANSI 파일 선택 | 별도 진단 기록 뷰어 |

동일 프로젝트라는 이유만으로 대화 ID가 같다고 가정하지 않는다. 현재 구현은 매 진입 시 대화를 선택하며, 이미 선택한 대화와 CLI의 자동 연결은 제공하지 않는다. 목록은 최대 최근 300개이므로 오래된 모든 대화에 접근하는 전체 카탈로그는 아니다.

| ID | 상세 요구사항 | 수용 기준·현재 제한 |
| --- | --- | --- |
| H01 | 대화 원본은 CLI 저장소 | Claude JSONL 및 지원하는 Codex SQLite/legacy JSONL을 읽고 원본 내용은 변경하지 않음 |
| H02 | 대화 텍스트 중심 표시 | 사용자 요청과 assistant 텍스트를 구분; 도구 호출·결과·추론·TUI 상태줄 제외 |
| H03 | 제한된 페이지 | 시작은 최신 구간, `p`/`n` 이동 시 누적 append 없이 페이지 교체, 최대 65,536자 및 설정 상한 준수 |
| H04 | 명시적 갱신 | `g`로 저장소를 다시 읽음; 자동 폴링·AI 호출 없음. 일반 history는 최신 구간, prompt는 마지막 저장 요청의 첫 구간으로 돌아감 |
| H05 | 읽기·복사·검색 | 읽기 전용·undo OFF·일반 영역 복사·현재 페이지 `C-s`; native 전체 대화 검색은 미구현 |
| H06 | 마지막 요청의 의미 표시 | “최근 저장된 사용자 요청”으로 표시하며 현재 처리 중인 요청이라고 단정하지 않음 |
| H07 | 원시 기록은 진단용 | 기본 OFF, 새 세션 생성 전 설정으로 활성화; 기존 기록은 보존하고 필요 시 명시적으로 열기 |
| H08 | 실패를 잘못된 내용으로 대체하지 않음 | 저장소 없음·지원하지 않는 형식·초과 크기·시간 초과 시 오류; 다른 최신 대화로 자동 대체하지 않음 |

Markdown 원문과 간단한 강조를 제공한다. native history의 색상은 CLI 화면을 복원한 것이 아니다. 진단용 ANSI 뷰어는 색상 코드를 기본적으로 색상으로 변환하며 `c`로 원시 코드 표시를 전환한다. 해당 진단 뷰어에만 `/` 파일 전체 검색과 `M-n` 다음 일치가 있다.

대기열 요청, CLI의 저장 지연, 분기·압축·재생 항목 때문에 마지막 저장 텍스트와 현재 활성 턴이 다를 수 있다. 첨부 원본과 저장 전 응답은 보이지 않는다. `q`로 조회를 닫아도 CLI 프로세스와 원본 대화는 유지한다.

### 6.2 Worktree — 변경 작업을 별도 디렉터리에서 수행하기

**목적:** 기존 작업 디렉터리를 유지하면서 다른 브랜치의 AI 개발 작업을 분리한다. R14의 상세 요구사항이다. EAM은 Git worktree의 생성·선택·CLI 시작·안전한 제거를 연결하며 브랜치 병합이나 작업 분배를 자동화하지 않는다.

**대표 시나리오:** 기능 A를 개발하던 중 버그 B를 수정해야 한다. `C-c a w c`로 저장소, 새 디렉터리, `fix/bug-b` 브랜치, 로컬 기준 `HEAD`를 지정한다. 생성 후 Dired에서 파일을 확인한다. `C-c a w s`로 그 worktree와 Codex를 선택해 수정·테스트를 요청한다. 작업이 끝나면 CLI를 종료하고 Git 변경을 정리한 뒤 `C-c a w d`로 worktree를 제거한다. 브랜치는 남는다.

| 명령 | 키 | 입력 → 결과 |
| --- | --- | --- |
| `eam-worktree-create` | `C-c a w c` | 저장소·새 경로·새 브랜치·로컬 기준 ref/SHA → 생성 후 Dired |
| `eam-worktree-open` | `C-c a w o` | 저장소 → 등록된 경로·브랜치 목록 → Dired |
| `eam-worktree-start` | `C-c a w s` | 저장소 → 등록 worktree → provider → 해당 경로에서 새 지속 CLI |
| `eam-worktree-remove` | `C-c a w d` | 저장소 → 등록 worktree → 정확한 경로 확인 → 제거, 브랜치 유지 |

네 명령은 구현되어 있으나 기본 M-x 후보에서 숨겨지는 보조 명령이다. 키의 `w`는 소문자다. 별도의 EAM worktree DB를 만들지 않고 Git의 등록 상태를 읽는다.

| ID | 상세 요구사항 | 수용 기준·현재 제한 |
| --- | --- | --- |
| W01 | 명시적인 새 작업 분리 | 새 로컬 경로와 새 브랜치를 요구하고 기존 경로·브랜치를 덮어쓰지 않음 |
| W02 | 로컬 기준으로 생성 | ref/SHA가 가리키는 로컬 커밋에서 생성; fetch·의존성 설치·AI 요청 없음 |
| W03 | 실제 등록 목록 선택 | 경로·브랜치·locked 여부로 후보 구분, 한글·공백 경로 처리 |
| W04 | 프로젝트와 CLI 연결 | 선택한 worktree 경로가 CLI의 작업 디렉터리가 됨; 기존 활성 세션 목록으로 이동·재접속 |
| W05 | 제거 시 실행 상태 보호 | worktree 내부의 알려진 CLI·Emacs 프로세스 또는 관련 지속 세션의 미종료/미확인 상태에서 거절 |
| W06 | 제거 시 파일 보호 | 미커밋 변경·미추적·ignored 파일·수정된 파일 버퍼가 있으면 거절 |
| W07 | 제거 대상과 결과 제한 | 사용 가능한 unlocked 보조 worktree만 제거; 주 worktree·bare·prunable·사라진 경로는 거절, 브랜치는 유지 |
| W08 | 자동 강제 복구 금지 | force 삭제·stash·reset·clean·prune·브랜치 삭제를 대신 실행하지 않음 |

CLI를 detach해도 작업이 종료된 것이 아니므로 worktree 삭제 허용 조건을 충족하지 않는다. `node_modules` 같은 ignored 파일만 남아 있어도 제거가 거절될 수 있다. 사용자는 남길 파일을 판단하고 정리한 뒤 다시 실행한다.

등록 정보와 디렉터리 위치는 일치해야 한다. 저장소·worktree를 Finder나 `mv`로 옮긴 경우 기존 절대 경로를 EAM이 자동 복구하지 않는다. 외부 터미널의 모든 프로세스나 검사와 삭제 사이의 외부 파일 쓰기를 완전히 탐지하는 보증은 없다. 원격 작업 경로와 임의 프로세스 강제 정리는 지원 범위 밖이다.

### 세션 목록·이름·알림 확인

`eam-new`/`eam-resume`은 현재 버퍼 디렉터리를 미니버퍼에 채우고 선택적인 세션 이름을 받는다. `eam-rename`은 이름만 변경하며 provider·대화 UUID·프로세스는 유지한다.

`C-c a l`은 전용 활성 세션 목록을 연다. 같은 디렉터리 그룹과 최근 PTY 입출력 정렬이 기본이며 생성·디렉터리·이름·provider·연결 상태·안 읽은 알림 순으로 바꿀 수 있다. `n`/`p` 세션 행 이동, `RET` 선택, `g` 갱신, `s` 정렬, `r` 이름 변경, `m` 알림 확인, `t` 그룹 전환, `f` detached 필터를 제공한다. 전체 순위를 보려면 그룹을 끈다. CLI 버퍼에서는 `C-M-n`/`C-M-p` 또는 `eam-next-session`/`eam-previous-session`으로 생성순 활성 세션을 순환한다. detached와 다른 Emacs가 점유한 세션은 건너뛰며 현재 Emacs에 연결된 세션만 순환한다. 기존 세션은 종료/분리하지 않는다.

세션의 연결 상태와 알림 읽음 상태는 별개다. 목록 열기나 단순 버퍼 표시만으로 확인하지 않는다. `RET` 성공 또는 `m`은 목록에 표시된 시점까지 확인하며 이후 새 알림은 안 읽음으로 남긴다. 이름과 읽음 위치를 세션별 별도 JSON에 보존한다. 분리된 세션 알림도 디스크의 이벤트 기록에서 제한된 분량을 읽어 표시한다.

최근 활동은 실제 PTY 입출력 시각이며 화면 갱신·터미널 응답을 포함한다. 요청/응답의 의미 분석이나 AI 호출은 없다. 목록 최대 256개, 수동 갱신, read-only·undo 비활성화를 유지한다. 구버전 데몬은 활동 시각이 없을 수 있다. 신규 목록의 실제 GUI 한글 조합·스크롤 체감 검증은 배치 테스트와 구분한다.

### 세션 헤더의 로컬 사용량

터미널 헤더에 계정명·확인 가능한 구체적인 플랜, provider 한도와 현재 session 토큰·컨텍스트를 구분해서 표시한다. 첫 줄은 계정·플랜·계정 사용 한도, 둘째 줄은 세션 토큰·컨텍스트만 표시한다. 대화 선택과 detach/quit 안내, provider/session/local account 접두사, 모델명은 없다. 두 줄은 EAM 버퍼의 tab-line/header-line을 사용한다. 원본 plan이 배수를 구분하지 않으면 추정하지 않고 선택적인 eam-account-plan-labels 표시명을 제공한다. `eam-usage`는 자동 정보 갱신 명령이다.

Codex는 공식 account/read·account/rateLimits/read·account/usage/read에서 계정 현황을 받고, CLI notify의 thread ID 및 실제 열린 파일로 대화를 자동 식별한다. Claude는 공식 statusline callback의 session ID·토큰·컨텍스트·한도 데이터를 받는다. 사용자 설정 파일은 수정하지 않고 시작 인수로만 연결하며 기존 notify/statusline 명령을 이어서 실행한다. AI 턴과 컨텍스트 삽입은 없다.

주간 한도 사용률과 토큰 개수는 서로 다른 값이다. Codex 일별 토큰은 제공된 최근 7개 UTC 날짜를 합산하고 누락 데이터는 0으로 단정하지 않는다. Claude의 주간 토큰 합계를 이 경로로 제공한다고 주장하지 않는다. 첫 이벤트 전에는 대기, 없는 한도는 미확인으로 표시한다. 구버전 실행 세션은 CLI 재개 후 callback이 적용되며 단순 attach로는 시작 인수가 바뀌지 않는다.

UI redisplay는 캐시된 숫자만 읽는다. 보이는 버퍼만 비동기 갱신하고 native reader 최대 2개, 결과 16KiB, 8초 deadline을 적용한다. Codex 계정 조회는 세션별 60초 캐시를 사용한다. 인증 토큰·callback 대화 내용은 보관하지 않는다. 계정 정보는 실행 중인 CLI의 메모리 인증과 다를 수 있으므로 출처와 시각을 도움말에 제공한다.

### 6.3 Worktree·세션·History 연결

Worktree로 변경 작업을 분리하고 해당 경로에서 지속 CLI를 실행한다. 과거 요청과 응답은 history로 읽으며, Emacs 재시작 후 살아 있는 CLI는 attach로 연결한다. 종료된 대화는 resume으로 새 CLI에서 재개한다. CLI 종료와 변경 파일 정리를 확인한 뒤 worktree를 제거한다.

Workspace 저장·복원 기능과 `C-c a s` 접두사는 사용자 요청으로 제거했다. 기존 workspace JSON은 삭제하지 않으며, 현재 제품에서 읽거나 복원하지 않는다. 향후 구체적인 요구가 생기면 별도로 검토한다.

## 7. 명령과 키 계약

기본 접두사는 선택적으로 켜는 `eam-keys-mode`의 `C-c a`다. 사용자 설정으로 재매핑할 수 있다. Ghostel char 모드에서는 `M-RET`으로 기본 입력 모드에 돌아와 Emacs 키를 사용한다.

| M-x 명령 | 기본 키 | 사용자 의미 |
| --- | --- | --- |
| `eam-new` | `C-c a n` | 현재 디렉터리 기본값·선택적인 이름으로 새 CLI 세션 |
| `eam-rename` | 목록 `r` | 사용자 세션 이름 변경 |
| `eam-usage` | M-x | 헤더에 표시할 저장 대화 사용량 연결 |
| `eam-sessions` | `C-c a l` | 활성 세션 목록·선택; prefix는 detached만 |
| `eam-attach` | `C-c a a` | detached 목록에서 재접속 |
| `eam-detach` | `C-c a d` | 화면 분리 |
| `eam-quit` | `C-c a q` | 확인 후 소유 CLI 서버 종료 |
| `eam-resume` | `C-c a r` | 새 CLI에서 저장 대화 재개 |
| `eam-status` | `C-c a i` | 프로세스·연결 상태 진단 |
| `eam-edit-input` | `C-c a e` | CLI 기존 입력을 일반 버퍼로 편집 |
| `eam-draft` | `C-c a b` | 독립 보조 초안 |
| `eam-paste` | `C-c a p` | 초안을 CLI에 전송, Enter 제외 |
| `eam-history` | `C-c a h` | 현재 프로젝트의 저장 대화 선택 |
| `eam-history-open` | `C-c a o` | provider부터 선택; prefix는 원시 기록 파일 |
| `eam-prompt` | `C-c a u` | 선택한 대화의 마지막 저장 요청 |
| `eam-notifications` | `C-c a m` | 알림 목록 |
| `eam-review-selection` | `C-c a v` | 선택 diff 리뷰 초안 |
| `eam-caffeine-mode` | `C-c a f` | 잠자기 방지 전환 |
| `eam-keys-mode` | 기본 키 없음 | EAM 키 활성화·해제 |
| `eam-help` | `C-c a ?` | 사용 안내 |

위 18개가 기본 M-x 후보다. 보조 명령은 구현되어 있지만 기본 자동완성에서 숨겨질 수 있다. `eam-focus`는 `C-c a t`, 선택 영역의 초안 추가는 `C-c a y`, worktree는 `C-c a w c/o/s/d`이다. provider별 시작 명령과 `C-c a P` 접두사는 제공하지 않는다.

버퍼별 후속 동작도 계약의 일부다.

| 버퍼 | 키 | 결과 |
| --- | --- | --- |
| 외부 편집 버퍼 | `C-c C-c` / `C-c C-k` | 저장·반환 / 원문 복원·반환 |
| 보조 초안 | `C-c C-c` | 붙여넣기만 수행 |
| native history·prompt | `p` / `n` / `g` / `q` | 이전·다음 페이지 / 새로 읽기 / 조회 닫기 |
| native history | `C-s` | 현재 페이지 검색 |
| 알림 목록 | `RET` / `r` / `g` / `q` | 이동 / 읽음 전환 / 갱신 / 닫기 |

`C-x C-s` 같은 일반 Emacs 저장 동작을 CLI 반환 명령으로 취급하지 않는다. 편집 버퍼의 commit과 CLI의 요청 제출은 별개다.

## 8. 데이터·인증·운영 요구사항

### 8.1 데이터 책임

| 데이터 | 저장 주체·위치 | 정책 |
| --- | --- | --- |
| 원본 요청·응답 | Claude/Codex의 로컬 저장소 | EAM이 읽기만 함; provider 저장·삭제 정책 적용 |
| EAM 세션 정보·소유권·알림 이벤트 | `eam-directory` 아래 | 프로세스 관리·재접속에 필요; 대화 전체의 복제본 아님 |
| 외부 편집기 작업 파일 | EAM 편집 연결 경로 | CLI 입력 왕복용; 대화 백업 아님 |
| 원시 터미널·명시적 입력 진단 | 활성화한 새 세션의 기록 경로 | 기본 OFF, 기존 기록 자동 삭제 없음 |

사용자가 선택한 운영 위치는 `~/.eam/`이다. **현재 코드 기본값은 여전히 `user-emacs-directory/eam/`**이므로 다음 설정으로 분리한다. 개인 설정 파일은 EAM이 자동 수정하지 않는다.

```elisp
(setq eam-directory (expand-file-name "~/.eam/"))
```

이 설정은 Claude/Codex의 원본 저장소를 이동시키지 않는다. native reader의 루트는 각각 `eam-claude-history-directory`, `eam-codex-history-directory`로 지정한다. 기본은 환경 변수 `CLAUDE_CONFIG_DIR`/`CODEX_HOME` 또는 `~/.claude`/`~/.codex`다. EAM 제거와 `.emacs.d`·전체 프로필 수동 삭제의 데이터 영향은 구분해서 안내한다.

### 8.2 로그인과 호출 경계

기존 구독 계정으로 공식 CLI에 로그인해 사용하는 것이 제품의 의도된 경로다. EAM은 자체 API 키 발급·모델 API 서비스·별도 과금 계층을 요구하지 않는다. 실제 CLI의 인증 선택·추가 사용량·조직 정책·모델 한도는 provider와 사용자의 CLI 설정에 달려 있다. 초기 JSON 어댑터의 API 인증 차단 검증을 현재 터미널 경로 전체의 과금 보증으로 확대하지 않는다.

알림은 예외적으로 CLI 실행 인자를 구성한다. Claude는 알림용 command hook, Codex는 터미널 알림 옵션을 사용한다. 프롬프트 수집 훅은 제거되었으며 개인 CLI 설정에 영구 설치하지 않는다. 기존 실행 프로세스에는 시작 당시 인자가 남으므로 패키지 삭제·설정 변경만으로 그 프로세스의 동작이 바뀐다고 안내하지 않는다.

### 8.3 설치와 의존성

검증 기준은 Apple Silicon macOS, Emacs for Mac OS X 30.1, Ghostel 0.53.0이다. 실행 시 Python 의존성은 없다. 처음 사용할 때 Rust/Cargo와 C 빌드 도구로 native runtime을 컴파일하고 eam-directory 아래 플랫폼·소스 해시별로 캐시한다. 설치/로딩만으로는 빌드하지 않으며 M-x eam-native-build로 수동 실행할 수 있다. 상세 조건은 [native runtime](native-runtime.md)을 따른다. Git은 worktree 기능에 필요하고 macOS 배너와 Magit 리뷰에는 선택 의존성이 있다. 다른 플랫폼·모든 CLI 버전의 지원을 보증하지 않는다.

기존 Emacs의 소스 로딩/use-package 설정과 package.el·VC 설치 경로를 제공한다. 단순 로딩은 GUI를 열지 않는다. `scripts/start.sh`는 새 격리 GUI를 연다. 시험 tar는 제품 파일 중심으로 구성하고 테스트·실험 파일을 제외한다. VC checkout에는 개발 파일이 남을 수 있으나 `.elpaignore`로 컴파일 대상에서 제외한다. 공개 패키지 저장소 등록·자동 업데이트·자동 데이터 마이그레이션은 현재 제공하지 않는다.

## 9. 비기능 요구사항과 실패 처리

| 항목 | 현재 기준 | 의미와 한계 |
| --- | --- | --- |
| native 페이지 | `eam-buffer-limit`, 최소 실효 128자·최대 65,536자 | 현재·이전 페이지 동일, 전체 RSS 제한 아님 |
| 출력·입력 undo | 출력 OFF, 사용자 입력 ON | 입력과 undo의 무제한 증가까지 막는 정책은 없음 |
| 터미널 표시 | 기본 16ms 재표시 묶음 지연 (`eam-terminal-redraw-delay`로 조정), Ghostel 스크롤백 예산 5MiB | 프레임 속도 보증·CLI 메모리 상한 아님 |
| native reader | 개별 행 8MiB, 결과 2Mi 문자, 30초 제한·취소 가능 | 큰 대화는 페이지마다 순회해 지연될 수 있음 |
| 대화 목록 | 최근 최대 300개, Claude 최대 10,000개 파일 탐색 | 전체 저장소를 모두 목록에 표시한다는 보증 없음 |
| 활성 세션 조회 | 최대 256개·10초, C-g 취소 | 미확인을 종료로 판정하지 않음 |
| 보조 초안 전송 | 64KiB, 여러 줄은 bracketed paste 필요 | 붙여넣기 후 사용자가 CLI 입력 확인 |
| 리뷰 선택 | 기본 12,000자 | 토큰 수 아님, 초과 시 선택 축소 요구 |
| 알림 메모리 | 기본 100건, 제목·본문 각각 2,048자 | 디스크 이벤트의 자동 보존 기간 정책과 별개 |
| 연결 소유권 | 전용 서버, 한 Emacs 표시 연결 | 소유한 세션만 종료 |
| 데이터 보존 | 기존 기록 자동 삭제 없음 | 디스크 자동 정리·전원 장애 무손실 보증 없음 |

오류는 다음 원칙으로 처리한다.

- CLI 실행 후 표시 연결만 실패하면 기존 세션 위치를 알리고 재접속 가능성을 유지한다. 같은 작업을 자동 재실행하지 않는다.
- 서버 소실·소유권 오류를 성공한 종료로 바꾸지 않는다. 미확인 상태에서 worktree 삭제 보호를 유지한다.
- native 저장 형식이 호환되지 않거나 크기 제한을 넘으면 오류를 알린다. 끝의 미완성 JSONL은 다음 갱신까지 제외한다.
- history는 저장된 텍스트 스냅샷이다. `g`로 갱신하며 현재 진행 중 작업이나 미저장 응답을 추정하지 않는다.
- 강제 종료가 임의 daemon·분리 자식까지 모두 정리한다는 보증은 하지 않는다.
- Caffeine은 현재 Emacs의 수명에 묶인다. Emacs가 종료되고 CLI만 남은 상태의 잠자기까지 계속 막지는 않는다.

## 10. 검증 근거와 성공 판정

### 10.1 확보한 근거

| 구분 | 확보한 근거 | 확대 해석하지 않을 사항 |
| --- | --- | --- |
| 로컬 자동 시험 | 한글·여러 줄 왕복, 입력/출력 undo, 세션 격리, 실패 정리, 제한 페이지, 원본 불변 | 물리 키보드 IME 성공 |
| 설치 시험 | 제품 컴파일·autoload·설치 위치 worker·PTY·Magit·제거 후 기록 보존 | 모든 개인 init·의존성 조합 지원 |
| 과거 실제 CLI | 양쪽 파일 수정·테스트·모델 선택·재개·알림 등 호환표의 시나리오 | 모든 slash 명령·최신 CLI 버전 호환 |
| GUI·사용자 보고 | 일반 버퍼 한글 입력·수정, 세션 선택, 편집·재접속, 별도 배너 확인 | 모든 IME·장시간 GUI 무결함 |
| native history 변경 | 실제 로컬 Claude/Codex 읽기와 가짜 형식 회귀, 배치 다중 뷰어 | 새 GUI 한글 조합·스크롤 검증 완료 |

2026-09-13 native 측정에서는 실제 Codex legacy 대화 4,252,124자를 65,536자로 제한해 표시했다. 200만 한글 문자 응답의 조회 버퍼 1/4/12개는 누적 65,536/262,144/786,432자를 유지했다. 각 단계의 추가 열기 시간은 0.043/0.125/0.337초, 배치 타이머 최대 간격은 67ms였다.

아래는 Rust 전환 이전 Python 구현의 측정이며 현재 native 성능 수치가 아니다. 실제 저장소 목록과 3개 페이지 조회의 Python tracemalloc peak는 Claude 약 1.2MB, Codex 약 33.7MB였다. 이는 한 번의 측정이며 전체 프로세스 RSS·장기 누수·GUI 프레임 지연의 보증이 아니다. 상세 조건은 [native history 검증](native-history.md)에 있다.

### 10.2 제품 성공 기준

0.1.0의 성공은 새로운 AI 기능 수보다 일상 개발 흐름의 완결성으로 판단한다.

- 선택한 provider·프로젝트에서 파일 수정과 테스트를 수행하고 승인 UI를 사용할 수 있다.
- Emacs 종료 후 같은 CLI로 재접속하고, 종료된 대화는 별도 resume 흐름으로 이어갈 수 있다.
- 한글·여러 줄 입력의 편집·반환·취소 시 텍스트가 보존되고 자동 제출되지 않는다.
- 여러 세션과 긴 대화에서도 명시한 버퍼 상한을 지키며 잘못된 세션에 전송하지 않는다.
- 관리·조회만으로 EAM이 모델 요청을 제출하지 않는다.
- 설치·업데이트·제거가 개인 설정과 별도 기록을 예상 밖으로 변경하지 않는다.

실사용 성공률·반복 사용률·체감 지연 p95·지원 비용은 아직 계측하지 않았다. 이를 이미 달성한 KPI로 기재하지 않는다. 자동 원격 사용 추적은 이 문서의 제안 범위에도 포함하지 않는다.

### 10.3 향후 안정 배포 판정 기준 — 제안

현재 시험 패키지 제공과 안정 배포 승인은 구분한다. 향후 안정 배포 전에는 핵심 요구사항 R01–R11·R17–R18의 회귀 통과, 데이터 손실·잘못된 세션 전송·의도하지 않은 호출의 알려진 재현 오류 해소, 지정 지원 환경의 실제 GUI 핵심 흐름, 설치 문서와 코드 일치를 확인하는 것을 제안한다. 검증 결과에는 날짜·rev·CLI/Emacs/Ghostel 버전·자동/직접 관찰 구분을 남긴다. 구체적인 배포 일정과 성능 SLO는 아직 확정하지 않는다.

## 11. 남은 차이와 후속 우선순위 제안

다음 항목은 현재 제공 기능이 아니라 역기획 과정에서 확인한 후속 검토 대상이다. 구현 승인이나 일정 약속을 뜻하지 않는다.

| 우선순위 | 항목 | 필요 이유·완료 판단 |
| --- | --- | --- |
| 우선 | 사용 문서 단일 기준 정리 | 과거 시작 화면·키·task·원시 저장 설명 제거/이력 표시, 현재 명령 대조 |
| 우선 | 실제 GUI 핵심 흐름을 버전별로 확정 | 한글 조합·긴 history 스크롤·외부 편집·재접속을 동일 지원 조합에서 기록 |
| 우선 | native 저장 형식 변경 대응 | 지원 schema fixture와 오류 안내 유지, 분기·압축·재생의 표시 정확도 기준 결정 |
| 다음 | 세션과 native 대화의 정확한 연결 | 반복 선택을 줄이되 최근 파일로 추측하지 않는 식별 근거 확보 |
| 다음 | detach와 미저장 초안 처리 통일 검토 | 자동 종료 시 보존과 직접 detach 시 닫힘의 차이를 사용자가 예측 가능하게 함 |
| 다음 | 상태·종료 명령의 선택 경험 통일 | 현재 버퍼 밖의 일부 진단/종료 경로가 내부 디렉터리를 요구하는 점 검토 |
| 다음 | 설치 설정 예제 정합성 | 선호 저장 위치 `~/.eam/`, 기본 OFF 옵션, 실제 키를 예제에 일관되게 반영 |
| 필요 시 | 전체 대화 검색·큰 대화 접근 속도 | 페이지 재순회 비용을 줄이되 중복 저장·메모리 증가와 비교해 결정 |
| 필요 시 | 디스크 기록·잔여 runtime 관리 | 오래된 진단/이벤트 정리의 보존 정책과 사용자 통제 정의 |

제3 provider, 원격 실행, 첨부 통합, 자동 에이전트 실행, task 기능 복원은 승인된 다음 단계가 아니다. 현재 사용 흐름을 검증하기 전에 기능 수 확대를 목표로 하지 않는다.

## 12. 결정 이력과 근거

### 12.1 제품 방향에 영향을 준 결정

| 초기 접근·요청 | 최종적으로 반영한 방향 | 이유 |
| --- | --- | --- |
| 일반 버퍼 스트리밍 우선 실험 | 실제 CLI 터미널 + 선택적 일반 편집 버퍼 | CLI 자체 명령·파일 수정·승인 기능 유지 |
| provider별 명령·긴 이름 | `eam-*`와 실행 시 provider 선택 | 명령 수와 기억 부담 감소 |
| 일반/지속 세션 구분 | 모든 실제 사용자 세션 지속 | Emacs 재시작 후 재접속 수요 |
| 시작 화면·메뉴 | M-x와 키 중심 | 사용자의 실제 작업 방식 |
| 프로젝트 task 관리 | 제품에서 제거 | 사용자에게 불필요한 범위 축소 |
| 원시 터미널 기록 중심 history | CLI 원본 대화 조회, 원시 기록 기본 OFF | 읽기 품질 개선과 중복 저장 감소 |
| 별도 제출 프롬프트 수집 훅 | native 마지막 요청 조회 | 별도 수집·설치 부담 감소 |
| 많은 반복 수동 검증 요청 | 자동 검증 선행, GUI 관찰은 필요한 항목만 구분 | 사용자 개입 부담 감소 |
