# Git worktree와 CLI 연결

`lisp/eam-worktree.el`은 Git 원본 worktree 명령을 argv로 호출한다. 사용자 입력을 shell 문자열로 실행하지 않는다. 개인 설정 변경·자동 fetch·의존성 설치·컨텍스트 삽입은 하지 않는다. 명령과 소문자 `C-c a w` 키의 상세 사용법은 [사용 안내](user-guide.md)를 따른다.

생성 시 저장소·새 경로·새 브랜치·로컬 기준 ref/SHA를 받는다. 생성/조회 후 Dired에서 파일을 보고 선택한 worktree에서 provider CLI를 시작할 수 있다. 생성·탐색만으로 AI를 호출하지 않는다. 실행 후에는 일반 세션 목록에서 디렉터리·이름으로 찾는다.

등록 목록은 `git worktree list --porcelain -z`로 읽어 공백·한글·개행 경로를 구분한다. `.git`이 파일인 linked worktree와 bare 저장소를 처리한다. `~` 경로는 Git 호출 전에 절대 경로로 확장한다. GUI가 반환한 `~/...`를 Git에 그대로 전달해 실패하던 문제의 수정이다.

## 삭제와 실패 경계

주 worktree, bare 경로, 잠긴/사라진 등록, 실행 중인 EAM CLI 또는 해당 프로젝트의 Emacs 프로세스, 미저장 파일 버퍼, 미커밋·미추적·ignored 파일이 있으면 제거를 거절한다. 제거 후 브랜치는 남긴다. 강제 삭제·stash·reset·clean·prune은 자동 실행하지 않는다.

다른 Emacs나 외부 터미널의 모든 프로세스를 탐지하지 않으며, 검사와 삭제 사이 외부 파일 쓰기를 원자적으로 막지 못한다. Git의 추가 거절도 그대로 표시한다. checkout 실패가 부분 상태를 남기면 강제 재실행/자동 삭제로 복구하지 않는다.

원격 추적 ref도 로컬에 저장된 커밋을 사용한다. 최신 원격 상태로 표시하지 않는다. CLI의 프로젝트 신뢰 승인은 제공자 자체 절차이며 worktree 생성 성공과 별개다.

`tests/worktree-test.el`은 임시 Git 저장소에서 격리·중복 거절·경로·bare·삭제 보호·브랜치 보존을 검사한다. 과거 실제 CLI의 cwd와 선택 경로 일치를 확인했으나, 신뢰 화면까지 실행한 검사를 모델 작업 완료로 간주하지 않는다.
