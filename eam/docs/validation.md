# 검증 요약과 한계

2026-09-17 문서 정리 기준. 원시 로그·스크린샷·시험 JSON은 docs에서 제거했다. 과거 Git 이력에서 원본을 확인할 수 있다. 아래 과거 수치는 기존 보고서의 요약이며 이번 정리에서 재실행한 결과가 아니다.

## 현재 재현 경로

저장소 루트에서 실행한다. 기본 suite는 실제 AI 호출이나 새 GUI 없이 컴파일된 가짜 CLI·PTY·Unix socket·임시 Git 저장소를 사용한다.

```sh
mkdir -p eam/var/validation
bash eam/scripts/test-native.sh > eam/var/validation/native.log 2>&1
bash eam/scripts/test-native-package.sh > eam/var/validation/package.log 2>&1
```

최초 Cargo 빌드는 의존성 다운로드가 필요할 수 있다. 설치 검사는 임시 프로필의 tar 설치·첫 빌드·캐시 재사용·Python 없는 실행·삭제 후 데이터 보존을 검사한다. 개인 Emacs 설정은 수정하지 않는다.

가장 최근 기능 변경(현재 세션 history 직접 열기)의 소스 검사 결과는 Rust 단위 8개 + 통합 25개, Emacs ERT 81개 통과다. quick→persistent 전환, 같은 PID로 detach/reattach, 메모 보존, 대화 ID 불일치 거절, 선택창 없는 조회를 포함한다. 설치본 33개 통과 기록은 그보다 앞선 세션 관찰 기능 단계의 결과이며 최신 소스 전체 설치 검증으로 읽지 않는다.

## 무엇을 검증하는가

| 층 | 확인 범위 | 대신하지 못하는 것 |
|---|---|---|
| Rust/ERT 가짜 CLI | 프로토콜·수명·분할 바이트·버퍼 상한·undo·파일 보존·오류 정리 | 실제 provider UI·한도·구독 응답 |
| 실제 CLI PTY | 로그인된 CLI 입력·수정·재개·승인·모델 메뉴 동작 | GUI 프레임 지연·물리 IME |
| Computer Use GUI | 표시·창·합성 입력·스크롤 관찰 | 물리 키보드 조합 이벤트의 동일성 |
| 사용자 물리 입력 | 해당 시점의 직접 한글 입력·수정·배너 관찰 | 모든 버전·경로·장시간 안정성 |

과거 입력 조사에서는 합성 입력이 일반 text-mode/TextEdit에서도 다르게 전달되는 현상을 분리했다. 세션 선택에서 사용자는 Space만 안 들어가고 한글 입력·수정은 정상이라고 보고했다. 한글 완성 문자열을 batch로 삽입하는 검사와 IME 조합 검사는 별개다. live 헤더의 바이트 증가만으로 입력·스크롤 정상 여부를 판단하지 않는다.

## 보존한 과거 측정

초기 일반 버퍼 프로토타입(2026-09-08, macOS arm64, Emacs 30.1, 같은 프로세스에서 순차 측정):

| 세션 | 1,000배치 디스크 합 | 출력 문자 상한 합 | RSS KiB (100→1,000배치) |
|---|---:|---:|---:|
| 1 | 5,994,786 | 65,536 | 43,296→48,944 |
| 4 | 23,979,144 | 262,144 | 76,112→80,752 |
| 12 | 71,937,432 | 786,432 | 85,984→88,592 |

12세션에서 과거 조회를 세션당 1,000→5,000회로 늘렸을 때 RSS는 96,064→97,520KiB였다. 별도 3초 타이머 실험의 heartbeat는 298회, 최대 예상 간격 초과는 69.36ms였다. 동기 삽입 시간이나 출력 상한이 전체 메모리·GUI 지연 상한을 증명하지 않는다.

초기 Ghostel/PTY 반복 정리 시험(2026-09-09, Rust 전환 전)은 4세션×4초를 16회 실행했다. 정리+GC 후 footprint 첫 회 약 35.52MiB, 마지막 약 36.22MiB, 범위 약 35.52~38.53MiB였다. 남은 프로세스 객체 1개(편집기 서버), 세션·타이머 0개, 버퍼 6개를 확인했다. allocator·네이티브 할당 전체의 분해나 수일 무누수 증명은 아니다.

초기 native history 이전 Python reader는 실제 로컬 목록과 3개 페이지 조회 시 Claude 0.059초/추적 peak 약 1.2MB, Codex 3.249초/약 33.7MB였다. 200만 한글 문자 가짜 응답의 조회 버퍼 1/4/12개는 각각 65,536/262,144/786,432자로 제한됐다. 이 수치는 **현재 Rust 구현의 속도·RSS가 아니다**.

과거 1시간 PTY 스트림 검사에서는 디스크 해시·한글 입력·제한된 과거 페이지를 확인했지만 footprint 변동도 관찰했다. 초기 저장 실패 시험의 오류 주입과 제한된 HFS+ 이미지의 실제 ENOSPC 시험, 별도 Emacs SIGKILL 후 완료된 append 보존은 전원 장애 무손실을 증명하지 않는다. 현재 native의 선택적 raw 기록 실패 처리와 과거 기록 필수 프로토타입의 중단 정책도 같지 않다.

최근 세션 목록 합성 검사: 256세션/32그룹 10회 렌더 약 0.083초, 26,583자. 파일 조회·GUI redisplay·네트워크 비용을 제외한 버퍼 생성 수치다. Claude 스크롤의 GUI 실측과 수정 후 미검증 범위는 [별도 조사](claude-scroll-validation.md)에 남긴다.

## 실제 CLI 확인 이력

초기 Emacs 30.1/Ghostel 0.53.0, Claude 2.1.263 계열·Codex 0.153.4에서 작은 파일 수정·테스트·승인 거절 후 복구·모델 변경·저장 대화 재개·한글/여러 줄 외부 편집기 왕복을 관찰했다. Claude의 유한 goal 수행·해제도 확인했지만 장기 goal 재개·모든 CLI 명령의 지원으로 일반화하지 않는다. 실제 Claude 2.1.266/Codex 0.153.4 알림 검사에서 완료·승인 요청 알림을 수신했고 개인 설정 파일을 수정하지 않았다.

작업 중단과 CLI 종료는 다르며 강제 종료 뒤 자식 작업 잔존 반례가 있었다. [설계 결정](design-decisions.md)의 종료 경계를 따른다. 비텍스트 첨부·모든 provider 버전·인증 만료·한도 소진을 모두 검증했다고 주장하지 않는다. 실제 CLI가 자체 훅/직접 셸 뒤 모델 응답을 만들 수 있어, 앱이 추가 요청하지 않는 것과 전체 호출 0회도 구분한다.

현재 남은 것은 Rust 장기 메모리·실제 GUI IME/트랙패드 체감, Claude 환경 전달 수정의 전후 비교, 복잡한 TUI 재연결 복원 범위다. 실행 로그는 `var/`에 남기고 새로 확인한 결론만 이 문서 또는 해당 기능 문서에 갱신한다.
