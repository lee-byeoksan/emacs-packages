# 세션 관찰·메모·임시 세션

2026-09-17. 버전 0.1.0 유지. 개인 Emacs/CLI 설정 변경 및 AI 요청 없음.

## 구현 범위

- `eam-sessions`: STATE(연결)와 WORK(작업)를 분리, CTX 비교·강조 및 context/work 정렬.
- `eam-status` / `eam-prompt`: 현재 EAM 세션에 연결된 대화만 자동 식별. 최근 요청과 미완료 도구를 표시. 별도 대화 선택 없음.
- CLI 헤더: 작업 상태, 한도 원본 경과 시간과 로컬 조회 시도 경과 시간을 구분. 조회 실패 시 마지막 정상 한도 유지.
- `eam-note`: 텍스트 메모, undo 유지, 명시적 저장, 최대 UTF-8 64 KiB. 실제 CLI 대화 ID에 연결하여 자연 종료/quit/resume 후에도 보존. ID 확인 전에는 pending 파일에 보관.
- `eam-quick`: provider만 선택, `eam-quick-directory` 사용. 최초 연결 이후 disconnect 시 종료. 최초 연결 실패도 30초 후 정리. 프로젝트 파일과 provider 대화 기록은 삭제하지 않음.
- `eam-persist`: CLI 재시작 없이 quick 자동 종료를 해제한다. daemon이 메타데이터 저장과 실행 중 수명 정책 변경을 확인한 뒤 성공한다. 대화·디렉터리·이름·메모는 유지한다. 구버전 daemon은 지원하지 않을 수 있다.
- `C-M-n/p`: 현재 창의 버퍼를 교체. 다른 창 유지, detached 자동 연결 없음.

## 배치·네이티브 검증

최신 소스 검사와 설치본 검사의 시점·범위는 [검증 요약](validation.md)을 따른다.

검증 항목:

- 병렬 도구 호출 중 하나만 완료되면 남은 도구를 계속 표시.
- Claude 도구 결과와 subagent 기록을 사용자 요청으로 오인하지 않음.
- Claude `stop_reason` 없는 텍스트 응답은 waiting~로 명시적으로 추정.
- 2 MiB 초과 로그에서도 마지막 1 MiB만 읽음. 범위 밖 프롬프트는 재사용/추측하지 않음. 마지막 미완성 JSON 줄은 무시.
- 대화 ID 불일치 거부, 읽기 전용 SQLite, provider별 기존 토큰 계산 보존.
- 메모의 detach/종료 보존, 두 provider의 다른 EAM 실행에서 같은 대화 재개, 다른 대화·프로필 격리, revision 충돌·기존 노트 이전 검사.
- 임시 세션 disconnect 종료와 일반 세션 disconnect 유지의 차이.
- 한도 조회 실패에도 마지막 정상 값과 원본 timestamp 유지.
- 메모 버퍼 undo/저장 및 CLI 종료 후 편집 보존.
- 두 Emacs 창 중 선택한 창만 next/prev로 교체하고 다른 창은 그대로 유지.
- 256개 세션/32개 그룹을 10회 렌더링: 약 0.083초, 26,583자. 이는 합성 목록 렌더링만의 수치이며 실제 파일 조회/GUI 렌더링 성능은 포함하지 않음.

PTY/Unix 소켓 검증은 샌드박스 밖에서 가짜 컴파일된 CLI로 수행했다. 테스트가 실제 Claude/Codex 모델 요청을 만들지는 않았다.

## 한계와 GUI 검증 구분

- 이번 배치 테스트는 실제 GUI에서의 한글 IME 조합, Ghostel 스크롤 체감, 화면 디자인의 시각 검증을 대신하지 않는다.
- 작업 상태는 CLI가 디스크에 남긴 마지막 관찰이다. 승인 대기/백그라운드 프로세스까지 정확히 분류하지 않는다. `~`는 추정, `unknown`은 근거 부족이다.
- 현재 도구는 최대 8개 이름이며 인자/전체 도구 출력은 복사하지 않는다. 요청은 1024자 미리보기이다. 데이터는 메모리를 통해 전달하고 새 대화 사본 파일은 만들지 않는다.
- 상세 조회는 기존 비동기 worker 제한(동시 2개, 8초, 결과 16 KiB)을 사용한다. transcript head/tail은 각각 1 MiB로 제한한다. 목록은 최대 8개 worker로 식별된 transcript만 읽고, 비싼 lsof/계정 RPC를 실행하지 않는다.
- 목록은 g로 갱신하는 스냅샷이다. 콜백/재개 ID가 아직 없는 새 세션, 오래된/기록이 지연된 세션은 작업·컨텍스트를 표시하지 못할 수 있다.
- 현재 CLI 버퍼가 보일 때 기존 주기(기본 10초)로 수집한다. detached 목록 조회도 저장된 대화 ID가 있으면 해당 원본 기록을 읽는다. detached 세션에 연결하거나 CLI를 다시 시작하지 않는다.
- 기존 실행 중 데몬은 자동 교체하지 않는다. 구버전 note.json은 CLI 종료 전에 새 코드로 이전해야 하며 이미 삭제된 노트는 복구할 수 없다.
